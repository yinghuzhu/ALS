## 本轮已确认的流程决策

1. 人工与主 agent 共同形成并确认需求、详细设计、测试用例；有歧义继续沟通。
2. 开发 agent 实现、单元测试、自测；主 agent Review 并要求开发修复，循环至可交测试。
3. 独立测试 agent 按确认用例执行并记录问题；主 agent 核验并交开发确认，明确缺陷自主修复，业务歧义交人工裁决。
4. 修复后主 agent 复查，测试 agent 复验与相关回归；所有必跑范围有证据后交人工最终验收。
5. 所有交付物未经明确批准均不提交 Git。上一轮提交许可不覆盖本轮；最终验收也不等于提交或部署授权。

## 实现选择

增加 `delivery-workflow` 作为主 agent 的阶段与交接入口；保留 `acceptance-qa`、`bug-record`、`release-delivery` 的专业职责，并修正团队模式下测试 agent 自行修复的问题。详细交接模板按需读取，不再造独立的通用开发或代码 Review skill。主 agent 负责设计与测试预期，不能因委派而转移责任。

验证采用独立测试 agent 的流程场景演练和文档结构检查。它们只能验证这些指令是否存在歧义或缺口，不能证明在真实项目上整套开发、Review、浏览器测试和发布已成功运行。

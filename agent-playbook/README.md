# 工程协作技能输出

本目录存放从 AI 会话中提炼的通用约束与可复用工作流程。它是输出目录，不会自动安装技能或覆盖其他项目规则。

- [AGENTS.md](AGENTS.md)：可供目标项目合并的共用约束；项目差异应显式说明，当前用户指令优先。
- [需求交付流程](skills/delivery-workflow/SKILL.md)：主 agent 编排需求讨论、设计与用例确认、开发、Review、独立测试和人工验收；[交接契约](skills/delivery-workflow/references/handoff-contracts.md)提供角色输入输出及关闭标准。
- [测试验收](skills/acceptance-qa/SKILL.md)：用例整合、受影响回归、独立执行及修复后复验。
- [缺陷记录](skills/bug-record/SKILL.md)：形成可复现、可分派的缺陷记录，区分待裁决、待复验和有证据的关闭。
- [根因排查](skills/root-cause-investigation/SKILL.md)：以证据解释原因、历史正常条件和失败触发变化。
- [发布交付](skills/release-delivery/SKILL.md)：基线、范围、制品、迁移、验收和回退。

## 默认分工与使用

用户与主 agent 共同形成并确认详细设计和测试用例；开发 agent 实现、单测、自测；主 agent 亲自 Review 并推进修复；另一测试 agent 按用例执行和记录问题。明确缺陷在团队内完成开发修复、主 agent 复查、独立复验，业务歧义交用户裁决，最终由用户验收并批准 Git。

完整需求使用 `delivery-workflow` 编排，已有确认从当前阶段接入；具体阶段复用所需技能。单次只读测试、排障或小范围修改不自动扩成完整流程。现有 `qa` 的测试修复循环不用于独立测试 agent；可用的 `review` 工具辅助主 agent，但不能代替其核验结论。

AGENTS.md 放共用约束与路由，skill 放阶段操作。完整新需求交付沿用既有文档，最低提供详细设计和唯一权威用例，运行说明与结果分开；单阶段任务只产出当前范围所需内容，不补建完整交付文档。不要因使用此目录再创建一套重复的实施计划、测试文件或问题清单。

## 路径与命名

Skill 内部相对链接以包含链接的文件所在目录为基准，例如 `delivery-workflow/SKILL.md` 中的 `references/handoff-contracts.md` 始终指向该 skill 内部资源，与调用时工作目录无关。项目产物中的 `docs/` 路径则相对实际目标项目根，或遵循该项目已有文档根约定，不写到 skill 安装目录。安装和工具目录在运行时发现，或由参数/环境提供；通用模板不绑定开发机用户名、仓库或临时目录的绝对路径，系统约定路径和 API 路径不受此限制。

既有明确命名约定优先；无约定的新记录采用：

- 缺陷：`docs/bugs/BUG-20261030-001-approval-group-resolution.md`。稳定 ID 是 `BUG-20261030-001`，后缀简要描述问题；当日编号须连同旧式无后缀记录一起查重，同一 bug 沿用记录。
- 完整需求：`docs/requirements/2026-10-30-approval-routing-policy/`。日期是首次建档日期，修订不改日期；目录内提供 `design.md` 和 `test-cases.md`，其他文件按需增加，单阶段任务不强制建立该目录。

描述后缀用有意义的小写英文 kebab-case，不用 `bug1`、`fix` 等模糊名称。不因模板变更批量改名历史记录；用户明确要求改名时保留稳定 ID/日期并同步引用和索引。

## 使用与维护

按目标工具的技能目录约定，复制需要的完整 skill 文件夹；AGENTS.md 单独评审合并到目标项目。当前仅是仓库内输出，未自动安装或覆盖全局技能。每个 skill 可独立使用，对其他技能的引用仅在其实际可读取时使用。目标项目的命令、环境、凭据和文档格式必须现场读取，不从历史记录直接照搬。

首版来源于 2,750 份归档文件的关键词筛选及抽样阅读。本轮对 2,766 份约 650 MB 备份做全文检索并精读相关上下文，不等同逐条人工读完所有历史，也不以归档文件数代替独立会话数。用户当前确认的角色和流程优先于历史个案；历史记录不赋予生产操作、外部消息或 Git 提交权限。

- [本轮历史证据与规则来源](evidence/2026-10-30-delivery-workflow.md)
- [流程验证用例](validation/workflow-test-cases.md)
- [流程验证报告](validation/workflow-test-report.md)

格式校验、规则审阅或流程场景演练均不等同真实项目端到端验证；实际验证范围与结果应在独立报告中说明，不写入用例文件作为固定结论。所有产物未经本次人工批准不得提交 Git；本次验收与提交权限分别核对。

后续按真实使用反馈迭代。候选扩展包括限定范围 Git 交付、设计评审、数据库迁移对账、文档一致性；当前不建立空目录。不要复制会话中的密码、Cookie、Token、真实客户数据到技能中。

# 测试与验收

先读取目标项目规则、既有测试用例与运行说明，确认测试对象、环境、改动范围和用户授权。遵循用户选定的浏览器、缓存和数据保留要求。

## 角色与进入条件

- 用例设计阶段由用户与主 agent 共同完成；设计和用例同版确认、实施获授权后才能进入相应开发。只要求用例设计时不擅自开始实现或业务测试。
- 完整需求交付中的测试 agent 必须不同于开发 agent，在主 agent Review 通过后接收待测版本与必跑清单。开发单元测试和自测不能替代独立测试；工具不支持独立执行者时报告限制，不能自行降级或虚构身份。
- 测试 agent 只执行、举证、记录和复验，不修业务代码、不更改业务预期或降低断言以获得通过。用户仅要求单次只读测试时按该范围执行，不强制补齐整个开发流程。

## 用例整合与影响分析（执行前完成）

1. 记录待测代码基线、相关未提交改动和需求版本。读取系统测试文档、相关模块用例及自动化测试实现，不能只确认文件或测试类存在。
2. 在本需求唯一的用例文件中整理新增/修改场景与人工步骤；旧用例引用原文件路径和稳定编号，不复制成第二份。保留自动化测试原有模块结构；命令及结果仍分别存放。
3. 对照前置条件、输入、操作、预期，建立覆盖映射：需求/受影响行为 → 用例路径与编号 → 复用/修改/新增/废弃 → 原因。相同编号不证明语义一致，不同编号也可能重复；不同测试层级的有效覆盖不应误删。
4. 发现冲突时提交主 agent 核对已确认需求和当前完整调用链。主 agent 在设计阶段修订有依据的旧预期并保留编号追溯；业务口径不明或预期改变需用户裁决，测试执行者不得自行选择一套预期。合并完成后更新原入口及交叉链接，避免留下两套权威用例。
5. 从改动入口追踪调用方、共享方法、数据读写和状态推进，列出受影响旧功能及必跑用例。重点检查默认行为、旧数据/旧客户端兼容、提交与退回、异步回调等实际涉及的路径，不机械套用无关场景。
6. 形成可交接的必跑清单：用例路径/编号、覆盖原因、环境与数据前提、执行负责人。准备可获得的测试数据；账号或权限缺失明确列为阻塞，不让执行者猜测。用例写清具体输入、操作及可观察预期，不能用“结果正常”或引用不存在的部署/回退方案制造覆盖。

## 工作流程

1. 从需求和实际实现形成场景矩阵，优先覆盖本次变化的正常、边界、失败和受影响旧流程；涉及权限、租户、重复请求或事务时覆盖相应隔离与一致性。
2. 区分预期与实现：金额、数量和状态依据业务规则独立推导预期值，不能直接复用被测算法作为断言。
3. 核对开发回传的单元测试/自测及主 agent Review 记录；单元测试 Mock 所有外部服务，数据库集成测试使用隔离环境，MySQL 使用 Testcontainers。浏览器验证实际部署产物，记录版本与入口。测试环境和数据独占或隔离，开发不得在同一待测工作区/产物/数据上并发修改；隔离副本中的开发不受此限。
4. 按风险执行相关层级。涉及代理或入口差异时分别验证直连与代理；涉及页面初始化时验证列表进入、深链和刷新。用户要求保留缓存时不得清缓存绕过问题。
5. 对业务链路核对页面输入、请求响应、数据库持久化、关联列表及汇总；例如采购新增后应付款同步可见，金额符合业务口径。
6. 失败时保存最小复现与证据，区分业务缺陷、环境/夹具问题和待裁决歧义。普通问题完成一轮后汇总给主 agent 与开发确认；阻断或污染立即报告，并继续独立可执行的用例。开发可提供反证，但不能单方否决测试证据。
7. 开发修复经主 agent Review 后，测试 agent 复验原失败用例和受影响旧功能，主 agent 核验结果后关闭问题。复验失败继续循环；业务歧义交用户裁决，不以改预期替代修复。
8. 实际执行必跑清单中的新增、修改和复用旧用例，报告通过、失败、未执行、阻塞；主 agent 核验逐项证据，不能仅凭“测试已完成”的总结。所有产物包括报告未经本次批准不得提交 Git；本 skill 不授权外部消息或生产操作。

每轮固定设计/用例、源码与制品版本。源码未提交时记录 HEAD＋完整差异和相关文件哈希（含未跟踪文件），无 Git 基线则记录文件清单与哈希，不为测试创建临时提交。源码、配置、数据前提或制品改变后由主 agent 重新核定 Review 和复测范围；不能混用旧报告证明新版本通过。

## 输出约定

沿用项目目录与格式，无约定时分开输出：
- 用例：编号、需求/缺陷关联、前置条件、测试数据、操作步骤、预期结果、清理条件。仅含可重复执行的用例。
- 运行说明：环境准备和测试命令。
- 执行报告：轮次、设计/用例版本、环境/源码/制品、执行时间、执行人、用例路径/编号及结果、实际观察与证据、缺陷编号、恢复情况、未执行/阻塞原因、人工验收入口。

测试数据只在授权环境创建和清理，不删除已有业务数据。证据中隐藏凭据与敏感信息。

## 完成标准

测试设计交付与执行验收分开：只要求设计时，完成覆盖映射和必跑清单，明确尚未执行。实施验收时，所有必跑项必须有实际执行结果；缺少结果的标记未执行或阻塞，不得宣布全部验收完成。检查类名存在、文档链接或静态格式不等于执行测试。

所有必跑项实际通过、必须修复的问题复验关闭且文档一致时，由主 agent 报告“待人工验收”，最终验收由用户确认。延期或不修需用户裁决并单列，不能计为通过。只通过单元测试时明确其边界，不宣称整个业务验收通过。

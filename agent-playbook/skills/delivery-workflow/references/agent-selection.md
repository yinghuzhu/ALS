# 执行者配置与默认发现名单

本配置由执行本 skill 的主 agent 读取，不是各 CLI 原生配置，也不是自动调度程序。默认不执行额外模型探测。

## 配置读取

在首次派工前读取本文件；优先采用当前用户明确选择，先读取本 skill 的 [agents.yaml](../agents.yaml)，再以目标项目根的 `agent-playbook.yaml` 覆盖；项目配置缺失时直接使用内置文件。内置配置缺失或无法解析时报告错误，不另用写死名单代替。项目配置不存在时不自动创建；用户要求保存默认值时再写入，Git 提交仍单独核对授权。

内置候选始终来自当前平台实际提供的子 agent 模型。CLI 候选以 `agents.yaml` 的实际内容为准；初始提供 `codex`、`claude`、`gemini` 三个命令，可直接增删或禁用；这是发现名单，不是已安装、已登录或服务可用的声明。配置的 `agents` 按 `id` 合并默认项，同 ID 覆盖所提供字段，新 ID 扩展列表，`enabled: false` 禁用；删除内置文件中的条目会从默认候选移除，项目覆盖要移除继承项时使用禁用；`builtin` 为内置入口且不可改成 CLI。`selection` 按角色、字段覆盖：省略字段继承内置值，显式 null 清除首选，空列表清除备用，非空备用列表整体替换、不追加。模型列表不写死，以当前工具能力、CLI 帮助及已配置模型为依据；无法列举时让用户提供型号并标记待运行验证，不猜型号。

## 项目配置格式

默认配置已独立保存为 [agents.yaml](../agents.yaml)，直接编辑该文件即可修改 CLI、模型和开发／测试的首选、备用；这里不再复制一份配置，避免内容不同步。


`models: auto` 表示主 agent 运行时核对，不表示 CLI 支持名为 auto 的参数。也可填明确模型 ID 列表；配置仅限制候选，不证明模型权限。`primary` 填 `{agent: 候选ID, model: 实际模型ID}`，`fallback` 为同结构的有序列表；空列表表示无自动备用。首选为 null 表示尚未选择。自动选择的授权范围和预算记入本需求交接记录，不以空值推定授权。

CLI 的 `command` 是单个可执行命令名或路径，不含参数、管道或 shell 表达式；不要用 eval 执行配置。命令名通过 `command -v` 查找，含路径分隔符的相对路径按定义该 command 的配置文件所在目录解析（内置配置相对 skill 目录，项目配置相对项目根），绝对路径只用于本机配置，不写入共享模板。需要参数时根据该版本帮助构造独立参数数组，任务内容通过适当的标准输入或文件传递。不得把密钥放入配置。

配置字段类型错误、重复 ID、未知候选引用、禁用的首选或模型不在显式候选列表时，报告具体问题，不静默回退到其他执行者。配置与当前用户指令冲突时以当前指令为准；不据配置扩大发送代码、费用、写入、提交或部署授权。

## 进度汇报配置

内置 `agents.yaml` 的 `progress.interval_minutes` 默认 10，用户可直接修改；目标项目 `agent-playbook.yaml` 中同名字段覆盖默认值。仅接受有限正数（分钟），缺省使用 10，零、负数、布尔值或其他类型均报告配置错误，不静默关闭汇报。更严格的平台沟通要求优先。

该间隔用于主 agent 向用户汇总所有运行中子任务；与 CLI 自身日志频率无关。具体执行、证据和无法定时恢复控制时的处理见 [执行流程](../SKILL.md) 的“执行期间的进度汇报”。

## 选择时机

设计和用例已确认、实施已授权后，首次开发派工前确定开发及测试两套选择；从测试阶段接入时，在首次测试派工前确定所需角色。已有有效选择或已授权自动选择则复用，否则展示统一候选表，让用户选首选、备用或授权自动选择。未获选择时可继续不依赖派工的工作，不启动尚未选定的执行者。

候选表使用 [交接契约](handoff-contracts.md) 的格式。内置模型和本地 CLI＋模型放在同一表中，标注待运行验证、已验证或不可用及成本是否核实。选择后只按已确认顺序处理服务故障，超出范围或所有候选不可用时报告。
